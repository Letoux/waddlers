# Frontend conventions (S2 auth UI)

UI language is French (D16). Auth API contract: see `BACKEND.md` ("What the frontend should call").

## Routes and guard

**Rules (security):** the layout guard is UX only. Every page under `app/(app)/` calls `await requireUser()` (`@/server/auth`, memoised over `getCurrentUser()`), because a client-side RSC navigation can render a page without re-running the layout (an anonymous replay with `RSC: 1` and a router state tree got the page content in the security re-audit). Server data is fetched only through `getServerClient()` (authed procedures); there is no direct `getDb` in `apps/web` (ESLint `no-restricted-imports` blocks `getDb`/`closeDb`, `drizzle-orm`, `postgres` and `@waddlers/server/*` in `app/api/**` and `server/**`; everywhere else `@waddlers/server` is blocked entirely).

- `app/login/page.tsx` (public): server component; redirects an already authenticated user to the validated `next` target (or `/`). Renders `components/auth/login-form.tsx`. No signup link or route exists.
- `app/(app)/layout.tsx`: calls `requireUser()` for the redirect UX and renders the shell (`components/app-header.tsx`: app name, username, "Paramètres", "Se déconnecter"). It is not the boundary. `error.tsx` (page errors inside the shell) lives there. There is deliberately no `loading.tsx` under `(app)`: a Suspense boundary above a page makes `notFound()` stream a 404 fallback with HTTP 200 (audit F2). Without it, an unknown or inaccessible space answers a real HTTP 404 (asserted in e2e); the positions list has its own loading skeleton, and the layout awaits the session lookup before anything streams anyway.
- `app/error.tsx` catches what the `(app)` layout and `/login` throw (session lookup with the database down); `app/global-error.tsx` is the last resort (own `<html>/<body>`). All render the neutral French `components/error-state.tsx`, never `error.message`.
- `proxy.ts` (Next 16 middleware) only sets an `x-waddlers-path` request header (overwriting any client value; tested) so `requireUser()` can build `?next=`. It is a convenience: removing it degrades to a plain `/login` redirect, it never decides access. The value is re-validated by `safeNextPath`.
- `app/(app)/settings/page.tsx`: change-password form.

## Login/logout behaviour

Forms call the browser client (`orpc.auth.*.mutationOptions()` from `@/lib/orpc`) via TanStack `useMutation`. After login and logout: `queryClient.clear()`, `router.replace(...)`, `router.refresh()` (the RSC guard re-runs). Expired sessions while the page is open: `QueryCache`/`MutationCache` `onError` in `components/providers.tsx` (`shouldRedirectToLogin`, `lib/auth/unauthorized.ts`) clears the cache and hard-navigates to `loginUrlFor(current path)` on any `UNAUTHORIZED`, except for the login mutation (bad credentials), logout (already signed out) and the login page. The submit button stays disabled through the redirect.

- `lib/auth/safe-next.ts`: `safeNextPath()` accepts only same-origin relative paths and returns the URL-normalised `pathname+search+hash` (dot segments such as `/..//evil` are resolved, then rejected if the result starts with `//`; `/login` is rejected case-insensitively; backslashes, control chars and scheme URLs too), falling back to `/`. `loginUrlFor()` builds the login URL.
- `lib/auth/errors.ts`: error code to French message. `UNAUTHORIZED` -> "Identifiant ou mot de passe incorrect."; `TOO_MANY_REQUESTS` -> wait duration from `data.retryAfterSeconds` (rounded up); `INVALID_CURRENT_PASSWORD` -> field error on the current password; anything else generic. Server `message`/`issues` are never rendered.
- `lib/zod-fr.ts`: French fallback messages for zod issues without an explicit message (e.g. the lenient login schema), scoped per form via `zodResolver(schema, { error: frenchIssueMessage })` (no global `z.config`). `too_small` with minimum 1 is "Ce champ est requis.", larger minimums "Valeur trop courte.". Explicit contract messages (password policy) win.
- Forms use React Hook Form + `zodResolver` with the contract schemas (`loginInputSchema`, `changePasswordInputSchema`, `newPasswordSchema`, `PASSWORD_MIN_LENGTH`); only the password confirmation is UI-specific. `components/ui/form.tsx` (shadcn pattern) wires `aria-invalid` / `aria-describedby` (hint + error). Field messages are always-rendered `aria-live="polite"` regions; `aria-describedby` only references ids that exist (the description only when rendered). Form-level errors use `role="alert"`. Server errors move focus to the relevant field (`form.setFocus`). Inputs are not disabled while pending (a disabled input cannot take focus); the submit button is.
- Success toast (`react-toastify`): "Mot de passe modifié." only. Login/logout errors are inline, not toasts (logout failure is a toast).

## Spaces and positions (S3)

API: `BACKEND.md` ("Spaces & positions (S3)"). Creating/renaming spaces and adding positions stay admin-only (CLI) in S3.

**Routes** (all call `requireUser()`; space pages also `requireSpace(spaceId)` from `@/server/spaces`, which turns an unknown, malformed or inaccessible id into the same `notFound()`):

- `/` (`(app)/page.tsx`): redirects to `/s/<activeSpaceId>` (from `spaces.list`), or shows "Aucun espace disponible. Contactez l'administrateur." when the user has none.
- `/s/[spaceId]`: dashboard (S5, see below); the "Titres suivis" count is taken from `spaces.get().positionCount`, never from `positions.list.total`.
- `/s/[spaceId]/titres`: `components/spaces/positions-list.tsx` (client, `useQuery(positions.list)` with `staleTime: 0`; loading, empty, error, NOT_FOUND and "liste tronquée" states; `lib/spaces/truncation.ts` is the only place that reads the cut-list flag). Replaced by the S6 table (see "Table (S6)"); `positions-list.tsx` and `truncation.ts` no longer exist.
- `/espaces`: accessible spaces with role and count, "Ouvrir" to switch.
- `(app)/not-found.tsx` (inside the shell) and `app/not-found.tsx`: neutral French "Page introuvable", identical for unknown and inaccessible ids.

**Space selection.** `(app)/layout.tsx` fetches `spaces.list` server-side and passes it as `initialData` to the client `AppHeader`, which shares the `spaces.list` TanStack cache. The current space is the one in the URL (`lib/spaces/nav.ts`), else `activeSpaceId`. The header selector (shadcn Select, label "Espace") pushes the same sub-page in the new space (`switchSpaceHref`) (it does not call the API itself). Space pages render `ActivateSpace`, the single `spaces.setActive` caller (`useSetActiveSpace`, silent on failure, never blocks rendering), which records the opened space once when it differs from the cached `activeSpaceId`. Nav: Dashboard, Titres (only with a space), Espaces, Paramètres; `aria-current="page"` marks the active item; below `md` a Sheet menu holds the links and logout while the selector stays in the header bar.

**Quantity input rules** (`lib/spaces/quantity.ts`, string-only, no float math; unit tests): blank means `null`; spaces (regular, no-break, U+202F) are accepted only as thousands separators in groups of three (`1 234 567`), so `1 2 3` is rejected; `,` or `.` is the decimal separator (not both); `,5` becomes `0.5`; the value is canonicalised (no leading zeros, no trailing fraction zeros, no bare separator: `5,0` is `5`), so an unchanged value is a no-op with no request and no toast. A single `.` followed by exactly three digits (`1.234`) is ambiguous for a French reader (1 234 or 1,234?) and is rejected with "Utilisez la virgule pour les décimales (ex. 1,234) ou un espace pour les milliers (1 234)."; `0.123` is accepted. The result is validated with the contract's `nullableQuantitySchema` (non-negative, at most 16 integer and 8 fraction digits). Display is fr-FR (`1 234,5`, U+202F group separator), `null` renders `—`, never 0 (0 is a real quantity). The raw listing currency is shown as is (`GBX` is never divided). Counts (positions of a space) use `toLocaleString('fr-FR')`, not the quantity formatter.

**Editing** (owner/editor only, from `SPACE_WRITER_ROLES`; viewers get read-only values): click, Enter or blur saves, Escape cancels. Invalid input keeps the editor open with an inline message; only the Enter path pulls focus back to the field (on blur the user has moved on). The mutation logic lives in `lib/spaces/set-quantity.ts` (pure, unit-tested with a QueryClient and a mocked mutation function; `use-positions.ts` only wires it to oRPC and toasts):

- edits of one position are serialized with a mutation `scope` (`qty:<positionId>`), so the last edit wins on the server;
- optimistic update touches that row only; a failure rolls back that row only, only if it still shows this edit's value and no other edit of the position is in flight, and falls back to the last value confirmed by the server (never to another edit's unsaved value);
- `positions.list` and `spaces.list` are invalidated on settle only when no other write of the space (edit or removal, tagged with mutation `meta`) is in flight, so a refetch cannot overwrite a value still being saved;
- success toasts "Quantité mise à jour." and updates one `aria-live` status ("Quantité de LVMH mise à jour."); FORBIDDEN toasts "Vous n’avez pas le droit de modifier cet espace."; NOT_FOUND refreshes quietly.

Query retries (`lib/query-retry.ts`): NOT_FOUND, FORBIDDEN, UNAUTHORIZED and BAD_REQUEST are never retried (a revoked space shows at once), other failures get two retries. The positions list state machine: NOT_FOUND on the list query (even with cached rows) renders "Espace indisponible" with a link to `/espaces`; any other refetch error keeps the rows and shows a "Données non actualisées." banner with "Réessayer".

Removal (`RemovePositionButton`): confirmation dialog, `positions.remove`, toast "Titre retiré de l’espace."; a double click sends one request and NOT_FOUND closes quietly; focus returns to the trigger on cancel, and to the list region (`role="region"`) when the row is gone (`onRemoved`, called from the mutation's `onSuccess` after closing).

Space switching: `ActivateSpace` (rendered by the space pages) is the only caller of `spaces.setActive`; the header selector only navigates (inside `useTransition`, the selector is disabled and `aria-busy` while the navigation is pending). If the URL names a space missing from the cached list, `spaces.list` is refetched once. The mobile table markup carries explicit `role` attributes (`table`, `row`, `cell`, ...) because the responsive CSS changes the `display` of table elements.

E2E data: global setup runs `pnpm db:seed` against the test database (`ALLOW_DEV_SEED=1`, random dev password) for reference data only. Every space scenario builds its own data inside the test (`e2e/support/fixtures.ts`): a fresh user (`user:create`), spaces, memberships and positions (`space:create`, `space:grant`, `position:add`; the space id is parsed from the anchored `Space created: <name> (<uuid>)` line), all with random names. Nothing is shared between tests, so `playwright test e2e/spaces.spec.ts --repeat-each=3` and retries are safe. The fixture also exposes `setRole`/`revoke` to change a membership after the page has loaded (FORBIDDEN and revoked-space cases). Specs: `e2e/spaces.spec.ts`. Seed selection reasons are stored in French ("Place principale (Euronext Paris)."); the CLI cannot set a reason, so they are only checked manually on the dev seed. Existing dev/test databases keep their older English reasons because the seed never overwrites rows.

Known limitation: a malformed percent-encoding in a space URL (`/s/%E0%A4%A`) is answered by Next itself with a plain-text HTTP 500 before any app code runs (no data is exposed); `parseSpacePath` only protects the header from throwing.

## Dashboard (S5)

API: `BACKEND.md` ("Dashboard (S5)"). Page `/s/[spaceId]` keeps the server header (name, role, "Titres suivis" from `spaces.get().positionCount`) and renders the client `components/dashboard/dashboard.tsx`. With `positionCount === 0` it shows "Aucun titre dans cet espace." and starts no dashboard request.

- **Period (specs 11).** Lives in the URL, `?periode=` with the contract ids (`1w|1m|6m|1y|5y|max`), validated by `parsePeriodParam` (`lib/dashboard/period.ts`; anything invalid, repeated or unknown falls back to the default `1m`, spec gives none). Labels are the spec's: Semaine, Mois, 6 mois, 1 an, 5 ans, Max. The selector (shadcn Select, label "Période") sits at the top of the dashboard, not in the header (no room next to the space selector at 375px). A change calls `history.replaceState` (no server round trip, no history entry; `useSearchParams` follows). The header carries the valid period through the space selector and the Dashboard/Titres links (`spaceHref`/`switchSpaceHref` take an optional period), so the period survives a space switch. The period will also drive the S6 table column "Performance période".
- **Queries (specs 28).** `lib/dashboard/queries.ts`: `orpc.dashboard.{summary,history,movers}.queryOptions({ input: { spaceId, period[, fxMode] }, staleTime })`, stale 60 s / 5 min / 5 min (BACKEND.md). Keys therefore include space, period and (history) fx mode, so returning to the dashboard within the staleTime starts no request (E2E asserts it). No server prefetch or hydration (first paint shows skeletons); a simple later optimisation.
- **Blocks.** `value-card.tsx` (total, period delta from `summary.change` with "depuis le <baseDate>", D5 partial-total warning with French reasons (`lib/dashboard/labels.ts`), D20 notice, price dates and a "Données anciennes" badge when stale: "Cours du <oldest> au <newest>" when `freshness.oldestPriceDate` and `newestPriceDate` differ, "Cours au <date>" when equal), `history-chart.tsx` (+ `value-plot.tsx`, `chart-tooltip.tsx`), `movers.tsx`. Every block has skeleton, error ("Les données financières ne sont actuellement pas disponibles." + Réessayer, never the technical message), empty and unavailable (`—`) states. Signed values use colour tokens `--gain`/`--loss` plus an icon and the explicit sign (`change-figure.tsx`), never colour alone. Sign, colour and arrow come from the ROUNDED DISPLAYED text (`displayedSign`): +0,4 EUR, -0,4 EUR and 0,04 % are shown as "0 EUR" / "0,0 %" and are neutral (no colour, no arrow, no sign), never a green "0 EUR". Formatting helpers (`lib/dashboard/format.ts`, unit-tested) format decimal strings for display only, dates from their parts in UTC.
- **Chart.** Recharts line (`LineChart`, `type="linear"`, no area fill), loaded with `next/dynamic` (`ssr: false`) so it stays out of the initial bundle; single series, colour token `--chart-line` (light and dark), `connectNulls={false}` (a gap day is a gap), compact y ticks ("128 k €"). Rationale for linear and no fill: every point is an end-of-day close, so straight segments between closes show exactly what is known; a smoothed (monotone) curve invents an intraday path and overshoots between points, and an area fill implies a baseline of zero that the auto y-axis domain does not show. The plot is `aria-hidden`; an `sr-only` summary (first/last/min/max) and a sampled table carry the data. Title "Valeur des positions actuelles" (D6), suffixed "au taux de change actuel" in current mode.
- **FX toggle (D22).** "Taux historique" / "Taux actuel" (two `aria-pressed` buttons) is chart-local state, part of the history query key. Tooltip = date, value, evolution % and one line per currency, `USD/EUR : 0,8807 (taux du 29/09/2026)` from `eurPerUnit` and `rateDate`; the rate has 5 significant digits whatever its magnitude (JPY `0,0058412`, KRW `0,00067321`), not 4 fixed decimals. The pence note ("Cours en GBX (pence), convertis via la livre (GBP).") is shown only when the rate's `quotedCurrencies` contains a minor unit (`GBX`, `ZAC`, `ILA`), so a GBP-only position gets none. In current mode points carry no rates: the tooltip and the line under the chart read `currentFxRates` once (a stale rate gets "(taux ancien)"). The chart shows a "Données anciennes" badge from `history.isStale`.
- **D23 (card vs chart).** The value card always uses `summary.change` (historical FX, even when the chart is in `current` mode, where the chart headline intentionally differs). Its end is the total (the D23 invariant `total - change = start` holds on the wire values), so the card shows no separate end date (the former `delta-end.ts` was dead under D23 and was removed). With a partial total `change` is null and the card says "Évolution : — (total partiel, évolution non calculée)"; with too little history, "pas assez de données sur la période". `freshness.oldestPriceDate` / `newestPriceDate` feed the price-date line; `history.seriesEnd` is not displayed.
- **429.** `dashboard.summary`/`history` can answer the typed `TOO_MANY_REQUESTS` (`data.retryAfterSeconds`). The dashboard queries (`summary`, `history`) retry it twice (`shouldRetryDashboardQuery`) after `retryAfterSeconds` clamped to 0.5-3 s (`dashboardRetryDelay`), because one period change fires both procedures and can touch the per-user cap; the app-wide default (auth) still never retries a 429. All three dashboard queries keep the previous answer while the next period or FX mode loads (`placeholderData`, only within the same space), so a quick change shows neither a skeleton nor an error flash. The block error (shown only once the retries are exhausted) reads only the code and the seconds ("Réessayez dans N secondes", `rateLimitedMessage`), never the server message, and keeps the Réessayer button.
- **D20 notice.** Positions whose stored history starts after the period start (`leadingMissing`): up to 3 names and not `max` gives "Pas de donnée avant le début de l’historique disponible de A et B"; more than 3 names or `max` gives "Historique complet disponible depuis le <baseDate> pour l’ensemble des positions — N titres sans historique plus ancien" with the names in a `<details>` disclosure (`leadingMissingNotice`). It is stored price history, not the listing's creation date, hence no "création".
- **Movers (specs 14).** "Plus fortes progressions" / "Plus fortes baisses" (spec 14 wording), 5 rows each: name, symbol, exchange, "depuis le <baseDate>", performance % in the listing's local currency with the currency shown ("en USD"). Rows are static with a title "Fiche détaillée bientôt disponible" until S9 adds the detail route (then wrap the row content in a `Link`).
- **E2E.** `e2e/dashboard.spec.ts` and `e2e/dashboard-states.spec.ts` (quick period/FX changes on `max` leave no error block, single and persistent forced 429, forced 500 error state with Réessayer, stale badge and price-date range, on-screen D23 invariant, GBP-only tooltip without pence note; the stale and GBP cases alter the answer with `page.route` because the fake market data is shared by all tests); global setup now runs `market:refresh <listing>` with `MARKET_DATA_PROVIDER=fake`/`FX_PROVIDER=fake` for AI, MC, SAP, MSFT, SHEL on the test database. CW8.XPAR is deliberately never refreshed (partial-total scenario).
- Layout gotcha: grid containers holding content that can be wide need `grid-cols-1` (implicit columns are `auto` and grow to min-content, which overflowed at 375px).

## Table (S6)

API: `BACKEND.md` ("Table (S6)"). `/s/[spaceId]/titres` renders `components/table/positions-table.tsx` (client orchestrator) over `positions-grid.tsx` (TanStack Table), `table-toolbar.tsx`, `pagination-bar.tsx`, `cell-view.tsx`. Logic is outside the components, in `lib/table/*` (pure, unit-tested): `url-state.ts`, `cells.ts`, `column-config.ts`, `pagination.ts`, `density.ts`, `use-table-positions.ts`.

- **TanStack Table v9** (`@tanstack/react-table` 9.2.x: `useTable` + `tableFeatures({ rowSortingFeature, rowPaginationFeature })`, NOT the v8 `useReactTable`). Manual mode (`manualSorting`, `manualPagination`, `rowCount`): the server sorts and pages, the table only models state (`state.sorting` from the URL gives `column.getIsSorted()`; clicks do not use TanStack's toggle order but `nextSort`). A real `<table>`; `aria-sort` on sortable headers only; the header button is keyboard-reachable; the scroll area is a focusable `role="group"`. Columns come from the registry through `resolveVisibleColumns(configured?)` (`lib/table/column-config.ts`): S6 passes nothing (D24 default); **S7 plugs the saved configuration (ids, order) there**, and the same ids feed the query `columns` and the table columns. The Actions column (remove) is added only for owner/editor and is not a registry column.
- **URL state** (`lib/table/url-state.ts`): `?q=` (search, max 100, NUL removed), `?tri=<column>:<asc|desc>` (validated by the contract whitelist `tableSortSchema`: unsortable, pending or unknown ids and a bad direction are ignored), `?page=` (1-based, bounded, `1` omitted), and the existing `?periode=`. Changes use `history.replaceState` like the dashboard period (no history entry). `applyTableUrlPatch` keeps the other params, and **drops `page` whenever search, sort or period change**. Sort cycle `nextSort`: none, asc, desc, none; a new column starts at asc. Search: the field is local state, the URL (hence the query) follows 300 ms after typing stops (E2E asserts one request). A page past the end (last row removed, hand-written URL) goes back to the last page.
- **Query** (`use-table-positions.ts`): `orpc.positions.list.queryOptions({ input: { spaceId, period, search?, sort?, page: { offset, limit: 50 }, columns }, staleTime: 60_000, placeholderData: keepWithinSpace(spaceId), retry/retryDelay: dashboard policy })`. One cache entry per combination, so returning to one within 60 s sends nothing; the previous page stays (dimmed, `aria-busy`, pager disabled) while the next loads, never across spaces. A 429 or in-flight-cap answer is retried twice after `retryAfterSeconds` like the dashboard; the error block (`BlockError`, "Réessayer") never shows the server message.
- **Cells** (`lib/table/cells.ts`, `cellView(def, cell)` returns text/tone/tooltip/stale/unavailable; `cell-view.tsx` renders it): money with its currency (`Intl` fr-FR, raw GBX kept) and "Cours du <date>"; perf = signed % (from `displayedSign`: a value rounding to 0,0 is neutral), gain/loss colour plus an arrow, tooltip "Depuis le <baseDate>"; fx = "1 USD = 0,8807 EUR" (specs 34 direction) with "Taux du <date>"; dates `dd/mm/yyyy`; decimals fr-FR; instrument type labelled. `null` or a missing key is "—" (never 0), with the French reason as tooltip (`reason` codes mapped, unknown codes say "Donnée indisponible"). **`pending_s8` columns** render "—" whatever the payload, tooltip "Donnée disponible prochainement". `isStale` adds a discreet "ancien" marker (price/perf on the price date, price EUR/tracked value also on the rate date, per the backend). Tooltips (shadcn `ui/tooltip.tsx`, one `TooltipProvider` per grid) are mouse-only; the same text is repeated as `sr-only` text in the cell. The header of "Performance période" is "Perf. <1 sem.|1 mois|6 mois|1 an|5 ans|Max>" (`columnHeader`); other headers use `shortLabel ?? label`, the full label in `title`. A non-sortable header says why in its title (`unsortableReason`: pending columns, and "Cours (devise locale)" which mixes currencies: "Triez par Cours EUR", D26).
- **Quantity**: the `quantity` column is `QuantityCell` fed by `row.quantity` (single source of truth; never `values.quantity`), same inline edit, parser and rules as S3 (owner/editor only; a viewer sees the value). `lib/spaces/set-quantity.ts` now works on a PREFIX key: `orpc.positions.list.key({ input: { spaceId } })` partial-matches every table entry of the space whatever its period/search/sort/page/columns (verified in `set-quantity-prefix.test.ts` with the real oRPC keys, other spaces untouched), through `getQueriesData`/`setQueryData`. While an edit is pending the row's `values.tracked_value_eur` is replaced by a "recalculating" cell shown as "…" (never computed on the client, never the old figure); a rollback restores both the quantity and the tracked-value cell of each page; after a success followed by a failure the quantity falls back and the tracked value stays "…" until the refetch. When no other write of the space is in flight, settle invalidates `positions.list`, `spaces.list` and `orpc.dashboard.key()` (quantities feed the dashboard). Remove keeps its S3 dialog, focus return and invalidations.
- **Density**: "Confortable / Compacte" (`lib/table/density.ts`, localStorage `waddlers.table.density`, every access in try/catch, applied after mount). Full configuration (D12) is S7.
- **Responsive (specs 39)**: the table sits in a `min-w-0 overflow-x-auto` container; `min-w-max` makes it scroll sideways inside it at 375px; the first column (Société) is `sticky left-0` with a background and a right border; no page-level overflow (E2E asserts scrollWidth, sticky offset after scrolling, and the last column reachable).
- **States (specs 36)**: skeleton rows (first load), "Aucun titre dans cet espace." (`data-testid="empty-space"`, empty space with no search), "Aucun titre ne correspond à « … »." (`no-match`), error with Réessayer, "Données non actualisées." banner when a refetch fails but rows are kept, "Espace indisponible" on NOT_FOUND, "Lecture seule" note for viewers. The toolbar (search, period, density, "N titres" count in an `aria-live` region) stays mounted across error/empty-result states so the search field keeps focus.
- **Not displayed yet**: the page-level freshness fields (`computedAt`, `oldestComputedAt`) and the row `descriptionTruncated` flag are read by no component (the D24 default has no description column; S7 adds it, render an ellipsis when the flag is true). When a freshness line is added, read the fields in one place only. `lib/spaces/test-fixtures.ts` builds test answers with the final contract.
- **E2E** (`e2e/table.spec.ts`; `e2e/spaces.spec.ts` adapted to the table, same intents): search by name/code/currency/accent ("societe" finds "Société Accentuée", a fixture added by `accent: true`), count, empty result, URL persistence, one debounced request; sort of Cours EUR and Perf. période asc/desc/none with nulls last, keyboard sort, bad `?tri=` ignored, pending column dash + tooltip; 60 positions in pages of 50 (range label, previous/next, page reset on search and sort); a quantity edit persists and doubles Valeur suivie, an edit on page 2 of a sorted table, remove, viewer has no edit controls; density persists, dashes for null, empty space, error + retry, stale marker; 375px scroll/sticky/no overflow. The 60 unpriced "Bulk NNN" instruments are created once in global setup and attached to a scenario space with `bulk: n` by `e2e/support/bulk.ts` (the only place in `apps/web` that talks to PostgreSQL directly: test-only, throwaway database, one narrow eslint-disable; the CLI adds one position per call, too slow for 60).

- **Gotchas (S6)**: `sr-only` text is `position: absolute`; inside an `overflow-x-auto` container that is not `relative` it escapes the clipping and widens the page (scrollWidth 1455 at 375px). The scroll container is therefore `relative`. Sorted-column E2E assertions poll (`toPass`) because the rows swap after the request. E2E and `pnpm test:integration` no longer share a database since afe1cdf (integration works on `<db>_int`), so they can run side by side; two concurrent runs of the same suite still collide.
- **Verified (2026-10-02)**: lint, format:check, typecheck, unit tests, build, full E2E (61 passed) and `table.spec.ts --repeat-each=3` (48 passed); dev-database walk at 1280 and 375 (sort, search `shell`/`usd`/accent, pagination label, quantity edit, sum of Valeur suivie on PEA = dashboard total to the euro, before and after an edit).

## E2E (Playwright)

`apps/web/playwright.config.ts` serves the production build (`pnpm build` first) on port 3100 against a **throwaway test database** (`E2E_DATABASE_URL`, default `postgres://waddlers:waddlers-test@localhost:5433/waddlers_test`; compose profile `test`): `docker compose --profile test up -d --wait postgres-test`, then `pnpm build && pnpm test:e2e`. A second server on 3101 points at an unreachable database (error-boundary scenario). Both get a test-only `AUTH_SECRET` from the config.

`e2e/support/global-setup.ts` checks the database with `test-support/safe-database.ts` (unit-tested: name must match `(^|_)test($|_)`, host must be local unless `CI`), runs `pnpm db:migrate`, and creates **one fresh random user per scenario** (`ACCOUNT_KEYS` in `e2e/support/env.ts`) through the admin CLI, so the login rate limit, the session revocation of `changePassword` and retries cannot leak between tests. Credentials are exposed to tests only via process env (`account(key)`). Existing servers are never reused. CI (`build-e2e`) provides a Postgres service on 5433 and sets `E2E_DATABASE_URL`.

## Known limitations

- Password field is not cleared after a failed login (clearing raced with fast retyping); the field is refocused.
- Playwright E2E covers Chromium desktop plus one 375px check; other browsers not run.
