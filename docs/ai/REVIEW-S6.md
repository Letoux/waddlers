As for S3 to S5, the original review texts are not reproduced: the findings below are the ones handed to the fix pass (subject-based numbering, `F<n>` / `P<n>` as in the brief). ## Security audit

| Ref | Sev | Finding | Status |
| --- | --- | --- | --- |
| Security P2 | P2 | `positions.list` was unbounded per user: a loop of concurrent calls could hold many pool connections (the S6 doc said "revisit") | **Fixed (limit, not a rate limit).** At most 4 calls of one user in flight, keyed by user id and procedure, through the shared `DashboardLimiter` with a per-call policy (`maxConcurrent: 4`, `rated: false`: no token bucket, so typing, sorting and paging never get a false 429 and the dashboard bucket is untouched). Typed `TOO_MANY_REQUESTS` with `retryAfterSeconds` and `Retry-After`, declared in the contract, after the access check (inaccessible space: `NOT_FOUND`). Tests: limiter unit (cap, no rate, per user/procedure) and integration (typed 429, other user and procedure unaffected, 40 sequential calls never refused, `NOT_FOUND` before 429). |
| Security P3-1 | P3 | Full instrument descriptions returned in bulk | **Fixed.** Same as Review F10 (280-character preview). |
| Security P3-2 | P3 | The IDOR matrix did not assert the page-level timestamps nor description content per space | **Fixed.** Space A's `computedAt` / `oldestComputedAt` equal A's own newest/oldest `computed_at` while space B holds a later one (and B's equal B's own); the matrix row already requests `description` and asserts that no other space's name appears. |
| Security P3-3 | P3 | The `LIKE` escape clause depended on `standard_conforming_strings` | **Fixed.** `ESCAPE E'\\'` (a single backslash whatever the setting) plus a comment; the wildcard tests (`50%`, `%`, `_`, `\`, `%%`, injection string) pass unchanged. |
